# AGENTS.md

This file provides guidance to AI coding agents when working with code in this repository.

## What this is

Felix Schröter's personal NixOS configuration flake, managing several NixOS hosts, two OpenWrt routers, and standalone home-manager profiles, all from one repo using `flake-parts`.

## Common commands

Rebuild the local system:
```sh
sudo nixos-rebuild switch
```

Rebuild and deploy to a remote host:
```sh
sudo nixos-rebuild switch --flake '/etc/nixos#<host>' --target-host user@hostname --use-remote-sudo
```

Deploy `home-server` via deploy-rs (see `deploy.nodes.home-server` in `hosts/flake-module.nix`):
```sh
deploy .#home-server
```

Check the whole flake (evaluates all outputs, runs the pre-commit hook check):
```sh
nix flake check
```

Build a specific output (mirrors what `.forgejo/workflows/test.yml` runs in CI):
```sh
nix build .#nixosConfigurations.<host>.config.system.build.toplevel   # home-pc, home-server, cmdframe
nix build .#homeConfigurations.<user>.activationPackage               # felschr, felschr-server, felschr-work
nix build .#deconz                                                    # custom package
```

Build an OpenWrt router image:
```sh
nix build .#doctr      # or .#penguin
```

Format Nix files / lint shell scripts (also runs automatically via the `pre-commit` git hook, installed by `direnv`/`nix develop`):
```sh
nixfmt <file>.nix
shellcheck <file>.sh
```

Enter the dev shell (provides the pre-commit hook setup):
```sh
nix develop
```
This repo uses `direnv` (`.envrc` runs `use flake`), so shells are usually loaded automatically on `cd`.

Update flake inputs:
```sh
nix flake update                          # all inputs
nix flake lock --update-input <input>     # a single input
```

There is no test suite beyond `nix flake check` / the CI builds above — correctness is verified by successfully evaluating and building the relevant `nixosConfigurations`/`homeConfigurations` output.

## Architecture

This is a `flake-parts` flake (see `flake.nix`), split into top-level modules that are imported in `outputs.imports`. Each area of the repo owns a `flake-module.nix` that contributes to `flake.*` (system-wide outputs) and/or `perSystem` (per-arch outputs):

- **`pkgs/flake-module.nix`** — custom packages (e.g. `deconz`), exposed as both `packages.<name>` and `apps.<name>`.
- **`lib/flake-module.nix`** — shared flake-level helpers exposed as `flake.lib.*`: `createSystemModule` (wraps a host's hardware+config modules and sets `networking.hostName`), `createUserModule` (from `lib/createUser.nix`; wires up a NixOS user + its home-manager profile together), `createMediaGroup`, and OpenWrt image builder helpers (`lib/openwrt.nix`).
- **`hosts/flake-module.nix`** — defines every `nixosConfigurations.<host>` (`home-pc`, `home-server`, `cmdframe`) and `diskoConfigurations`, and imports `hosts/doctr` and `hosts/penguin` (OpenWrt router image definitions built via `lib.mkOpenwrtImage`, not NixOS systems). Also declares the `deploy-rs` node for `home-server`.
- **`home/flake-module.nix`** — defines `homeModules` (reusable home-manager modules, including per-user profiles `felschr`/`felschr-server`/`felschr-work`) and standalone `homeConfigurations` for each profile.
- **`overlays/flake-module.nix`** — the single `overlays.default`, which pulls in `nixpkgs-unstable` as `pkgs.unstable`, injects locally built packages (e.g. `deconz`) into `pkgs`, and extends `vimPlugins`. Also exposes `pkgsFor system`, the canonical way every module gets an instantiated `nixpkgs` (with overlay + `allowUnfree` applied).

### Host composition pattern

Each `nixosConfigurations.<host>` in `hosts/flake-module.nix` is assembled from:
1. Upstream modules (`disko`, `nixos-hardware` profiles for the specific machine).
2. `self.lib.createSystemModule "<host>" { hardwareConfig; config; }`, which imports `modules/common.nix` (agenix + `flakeDefaults` + overlay wiring, shared by every host), `hosts/<host>/hardware.nix` (machine-specific, often generated by the installer — see README), and `hosts/<host>/default.nix` (the actual host config, itself composed of shared modules from `desktop/`, `hardware/`, `services/`, `system/`, `virtualisation/`).
3. `self.lib.createUserModule "felschr" { homeModule; user; usesContainers; }`, which creates the NixOS user and wires its home-manager profile (`self.homeModules.felschr*`) in one place — home-manager config is never defined ad hoc per host.

`hosts/<host>/default.nix` is a plain list of `imports` from the shared top-level directories (`desktop/`, `hardware/`, `services/`, `system/`, `virtualisation/`, `modules/`) plus host-specific config (networking, `age.secrets`, `system.stateVersion`, etc.). To see what a host actually runs, read its `default.nix` import list rather than searching for services by name.

### home-manager profiles

Three user profiles exist (`home/felschr.nix`, `home/felschr-server.nix`, `home/felschr-work.nix`) for the same physical user on different machine types (personal desktop, headless server, work laptop). They share `home/base.nix` and pull in feature modules from `home/desktop/`, `home/browsers/`, `home/editors/`, `home/shell/`, `home/services/`, `home/gaming/`, `home/modules/`. Each profile is both a `homeModule` (composed into a `nixosConfigurations` host via `createUserModule`) and a standalone `homeConfigurations.<profile>` (for use on non-NixOS or via `home-manager switch` directly).

### Secrets

Secrets are encrypted with `agenix` (`secrets/*.age`, decrypted via `age.secrets.<name>.file` in host configs). `secrets/secrets.nix` is the authoritative list of which host/user SSH public keys can decrypt each secret — update it (and re-`agenix rekey`) whenever access to a secret needs to change. New host installs need an initrd SSH key added to `secrets/secrets.nix` before secrets can be provisioned; see `README.md` for the full install/key-rotation flow.

### OpenWrt hosts

`doctr` and `hosts/penguin` are not NixOS systems — they're OpenWrt router images built through `lib.mkOpenwrtImage` (`lib/openwrt.nix`) and only exist as `perSystem.packages.<name>` outputs (`nix build .#doctr`), configured via UCI shell snippets rather than NixOS modules.

### CI

`.forgejo/workflows/test.yml` runs on every push/PR: `nix flake check` (non-blocking), then builds `deconz`, the `home-server` toplevel, and all three `homeConfigurations` activation packages. `home-pc` and `cmdframe` are commented out of CI (likely due to build cost/hardware-specific inputs) — check before assuming they're covered.
